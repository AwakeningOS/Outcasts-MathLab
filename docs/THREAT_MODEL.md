# Trust and Threat Model

Leanが緑になっただけで、元の数学問題が解けたとは限りません。このプロジェクトでは次の失敗を別々に防ぎます。

## 自動的に拒否するもの

- 未完了証明のプレースホルダー
- 新しい公理または定数による結論の注入
- `unsafe` 宣言による信頼境界の拡張
- 生成物や依存ディレクトリへ検査対象を隠すこと

`scripts/check_policy.py` は簡易ゲートです。完全なLeanパーサーではないため、CI通過後もレビューが必要です。

## レビューで拒否するもの

- 証明と同じPRで問題文を弱める
- 本来の定理ではなく有限個の例だけを証明する
- 既知の定理を再発見し、新規成果として報告する
- 結論そのものを含む外部定理を循環的にimportする
- 計算実験を一般証明として報告する
- 仕様と形式化の量化順序、定義域、境界条件が一致しない

## 許容する信頼基盤

- Leanカーネル
- 指定バージョンのmathlibとその依存
- GitHub Actionsの公開ログ
- 問題ごとに明記した追加依存

最終候補では `#print axioms` の結果をPRへ貼り、依存が許容範囲内か確認します。

## 外部コード

未知の提出コードを管理者の常設サーバーで直接実行しません。初期段階ではGitHub-hosted runnerを使い、権限を `contents: read` に制限します。秘密情報をPR用workflowへ渡しません。
